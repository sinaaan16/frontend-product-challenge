# کاتالوگ محصولات

این پروژه برای چالش فنی فرانت‌اند پیاده‌سازی شده و با **Nuxt 4 و Vue 3** توسعه داده شده است. برنامه شامل صفحه فهرست محصولات با قابلیت جستجو، فیلتر بر اساس دسته‌بندی و مرتب‌سازی، و صفحه جزئیات هر محصول است. اطلاعات محصولات از [Fake Store API](https://fakestoreapi.com/docs) دریافت می‌شوند.

## پیش‌نیازها و نحوه اجرا

برای اجرای پروژه به نسخه سازگار Node.js نیاز دارید. نسخه اجرای من برای این پروژه 24.19.0 میباشد..

ابتدا وابستگی‌ها را نصب کنید:

```bash
npm install
```

اجرای پروژه در محیط توسعه:

```bash
npm run dev
```

بعد از اجرا، برنامه از طریق آدرس [http://localhost:3000](http://localhost:3000) در دسترس خواهد بود.

برای ساخت نسخه نهایی:

```bash
npm run build
```

برای اجرای پیش‌نمایش نسخه ساخته‌شده:

```bash
npm run preview
```

## ساختار پروژه

بخش اصلی برنامه داخل پوشه `app/` قرار دارد. فایل‌ها و کامپوننت‌ها بر اساس وظیفه‌شان از هم جدا شده‌اند تا توسعه و نگهداری پروژه ساده‌تر باشد.

```text
app/
├── assets/
│   ├── css/main.css
│   └── img/
├── components/
│   ├── AppHeader.vue
│   ├── SiteNav.vue
│   ├── HeaderIcon.vue
│   ├── AppFooter.vue
│   ├── FooterIcon.vue
│   ├── CatalogFilters.vue
│   ├── AppliedFilters.vue
│   └── ProductCard.vue
├── config/
│   └── navigation.ts
├── data/
│   └── products.ts
├── layouts/
│   └── default.vue
└── pages/
    ├── index.vue
    └── products/
        └── [id].vue
```

### نقش بخش‌های اصلی

- **assets:** شامل استایل‌های عمومی و تصاویر استفاده‌شده در رابط کاربری، از جمله نمادهای اینماد و ساماندهی است.
- **components:** کامپوننت‌های قابل استفاده مجدد، مثل هدر، فوتر، فیلترها و کارت محصولات را در خود جای می‌دهد.
- **config/navigation.ts:** تنظیمات مربوط به منوی سایت و مسیرها.
- **data/products.ts:** تعریف تایپ‌های محصولات، تبدیل داده‌های API به ساختار موردنیاز برنامه و آماده‌سازی دسته‌بندی‌ها.
- **layouts/default.vue:** چیدمان مشترک صفحات را مدیریت می‌کند تا هدر و فوتر در بخش‌های مختلف سایت یکسان باشند.
- **pages/index.vue:** صفحه فهرست محصولات و امکانات جستجو، فیلتر و مرتب‌سازی.
- **pages/products/[id].vue:** صفحه جزئیات محصول که بر اساس شناسه محصول نمایش داده می‌شود.

## تصمیم‌های فنی

### ساختار و مسیریابی

پروژه از ساختار Nuxt 4 و مسیریابی فایلی {**file-system based** **routing** **system**} استفاده می‌کند. به این ترتیب، مسیرهای فهرست و جزئیات محصول به‌صورت خودکار از ساختار پوشه `pages` ایجاد می‌شوند.

همچنین، چیدمان مشترک باعث شده هدر و فوتر در هر دو صفحه حفظ شوند و نیازی به تکرار کد آن‌ها نباشد.

### رابط کاربری فارسی و واکنش‌گرا

رابط کاربری با در نظر گرفتن زبان فارسی و جهت راست‌به‌چپ (RTL) پیاده‌سازی شده است. فونت Vazirmatn برای نمایش بهتر متون فارسی استفاده می‌شود.

چیدمان صفحات نیز برای موبایل، تبلت و دسکتاپ تنظیم شده تا اجزای رابط کاربری در اندازه‌های مختلف صفحه به‌درستی نمایش داده شوند.

### مدیریت استایل‌ها

برای استایل‌دهی از CSS معمولی استفاده شده است. متغیرهای مشترک، رنگ‌ها و استایل‌های پایه در `app/assets/css/main.css` قرار دارند و استایل‌های اختصاصی هر کامپوننت در همان فایل Vue و با استفاده از `scoped` تعریف شده‌اند.

این روش وابستگی به کتابخانه‌های رابط کاربری اضافی را کاهش می‌دهد و مدیریت استایل‌ها را ساده‌تر می‌کند.

### مدیریت و تبدیل داده‌های محصولات

داده‌های دریافتی از Fake Store API پیش از استفاده در رابط کاربری، در فایل `app/data/products.ts` به ساختار داخلی برنامه تبدیل می‌شوند. دسته‌بندی‌ها و تعداد محصولات هر دسته نیز از داده‌های دریافت‌شده استخراج می‌شوند.

در نتیجه، منطق مربوط به آماده‌سازی داده‌ها از کامپوننت‌های نمایشی جدا می‌ماند.

### دریافت اطلاعات و مدیریت وضعیت‌ها

دریافت محصولات در سمت مرورگر انجام می‌شود؛ زیرا درخواست‌های سمت سرور به API در محیط توسعه با خطای `403 Forbidden` مواجه شدند.

وضعیت‌های بارگذاری و خطا در رابط کاربری مدیریت شده‌اند تا کاربر هنگام دریافت اطلاعات یا بروز مشکل، با صفحه‌ای بدون توضیح مواجه نشود. امکان تلاش مجدد نیز در نظر گرفته شده است.

### مدیریت جستجو و فیلترها

مقدار واردشده در فیلد جستجو از جستجوی اعمال‌شده جدا نگه داشته می‌شود. با انتخاب دکمه جستجو یا فشردن Enter، عبارت واردشده اعمال می‌شود و در فهرست فیلترهای فعال قرار می‌گیرد.

این تفکیک کمک می‌کند کاربر بتواند فیلترهای اعمال‌شده را مشاهده و در صورت نیاز حذف کند.

## فرضیات پروژه

- با توجه به امکانات Fake Store API و تعداد محدود محصولات آن، جستجو، فیلتر دسته‌بندی و مرتب‌سازی پس از دریافت اطلاعات، در سمت کلاینت انجام می‌شوند.
- مقادیر «رتبه» و «تعداد» از فیلدهای `rating.rate` و `rating.count` در پاسخ API گرفته می‌شوند.
- نام دسته‌بندی‌های انگلیسی API به معادل‌های فارسی تبدیل شده‌اند تا با زبان رابط کاربری هماهنگ باشند.
- لینک‌های بخش‌هایی مانند «درباره ما»، «سوالات متداول» و «دریافت مشاوره» در هدر و فوتر، صرفاً بخشی از رابط کاربری هستند؛ زیرا در محدوده این چالش، صفحه مستقلی برای آن‌ها تعریف نشده است.
- توضیحات محصول در صفحه جزئیات، برای هماهنگی با طراحی، به شکل فهرست بولت‌دار نمایش داده می‌شوند.
